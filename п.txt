# Повторный аудит OWASP Top 10 (2025) — АИС «Уют»

Итог: с прошлого раза исправлены 4 находки (`rate-limit` теперь нормализует логин, `open redirect` блокирует `\`, `payment_webhook` возвращает 501, демо-оплата обёрнута в `BEGIN IMMEDIATE`). Ниже — полный список.

## A01 — Broken Access Control

**Нашел.**

1. **`routes/admin.py` — `admin_logout` (строки с `@app.route('/admin/logout', methods=['POST'])`)**  
   - Нет `@admin_required`.  
   - **Вход:** POST `/admin/logout` с валидным CSRF-токеном, сделанный залогиненным гостем.  
   - **Выход:** `session.clear()` — гость разлогинивается сам.  
   - **Опасность:** низкая, но нарушает принцип «эндпоинты админ-зоны закрыты».

2. **`routes/features.py` — `toggle_promocode`**  
   ```python
   conn=get_db(); conn.execute("UPDATE Промокоды SET ... WHERE ID=?",(promo_id,)); conn.commit(); conn.close()
   return redirect(url_for('admin_promocodes'))
   ```
   - **Вход:** POST с валидным CSRF от админа.  
   - **Выход:** `BuildError` (нет `admin_promocodes` в корне, есть только в blueprint `features`). Админ видит 500.  
   - **Опасность:** низкая, но нарушает всю страницу промокодов.

3. **`routes/public.py` — `room_detail` (`/room/<id>`)**  
   Отдаёт имена гостей из отзывов: `SELECT r.*,c.Имя FROM Отзывы r JOIN Клиенты c ...`. Публичный эндпоинт.  
   - **Вход:** GET `/room/RM001`.  
   - **Выход:** имена и фамилии гостей, оставивших отзывы.  
   - **Опасность:** раскрытие ПДн. Средняя.

4. **`routes/features.py` — `export_guests` (`/admin/export/guests.csv`)** защищён `@admin_required` — чисто.

## A02 — Security Misconfiguration

**Нашел.**

1. **`app.py` — `add_security_headers`**  
   Заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `COOP`, `Permissions-Policy` есть, **`Content-Security-Policy` отсутствует**.  
   - **Вход:** любая инъекция inline-скрипта (например, через будущий `flash` с категорией из внешних данных или inline-template).  
   - **Выход:** CSP не блокирует.  
   - **Опасность:** средняя. Любая XSS становится неограниченной.

2. **`db.py` — `DB_NAME = os.path.join(BASE_DIR, "hotel_management.db")`**  
   Файл БД рядом с кодом. Проверить конфиг веб-сервера чтением кода нельзя, но это классический риск: при утечке статики через nginx/apache БД отдаётся целиком (пароли + ПДн).

3. **`templates/base.html` и `templates/admin/base_admin.html` — inline `<style>` в `booking.html`, `contact.html`, `room_detail.html`, `profile.html`**  
   Затрудняет введение строгого CSP.

## A03 — Software and Data Integrity / Supply Chain

**Нашел.**

1. **`templates/base.html` — строки 9, 11, 13**  
   ```html
   <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.0/dist/css/bootstrap.min.css" rel="stylesheet">
   <link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/css/all.min.css">
   <link href="https://fonts.googleapis.com/css2?family=Manrope..." rel="stylesheet">
   ```
   **Нет `integrity=` (SRI).**  
   - **Вход:** компрометация jsdelivr/cloudflare CDN.  
   - **Выход:** подмена CSS/JS в браузерах всех гостей и админов.  
   - **Опасность:** высокая. RCE на клиенте, кража сессий, keylogging.

2. **`templates/admin/base_admin.html` — те же строки с `bootstrap@5.3.3` и FontAwesome**  
   Та же проблема.

3. **`requirements.txt`**  
   ```
   Flask>=3.0,<4.0
   Pillow>=10.0,<12.0
   ```
   Нет lock-файла, нет точных версий. Диапазон `Pillow >=10.0` содержит версии с CVE (CVE-2023-50447 в <10.2, CVE-2024-28219 и др.).  
   - **Опасность:** средняя. Развёртывание может подтянуть уязвимую версию.

4. **`db.py` — `insert_test_data`, строки `print('DEV-ONLY credentials...')` и `print(f'Гость: ...')`**  
   Пароли печатаются в stdout при первом запуске → попадают в логи CI/контейнера.

## A04 — Cryptographic Failures and Secrets

**Проверил — в основном чисто.**

1. **`auth.py`** — `hash_password` использует `scrypt` через `werkzeug.security.generate_password_hash(method="scrypt")`. Политика: 12–256 символов. Чисто.

2. **`auth.py` — `password_matches`** — принимает только `scrypt:`, `pbkdf2:`, `argon2:`. Legacy-«сырые» пароли не принимаются. Чисто.

3. **`app.py` — `SESSION_COOKIE_SECURE = is_production or os.environ.get("SESSION_COOKIE_SECURE", "0") == "1"`**  
   В dev cookie едет по HTTP. Нормально для dev, но нет жёсткого запрета на prod без HTTPS.

4. **`db.py` — `add_admin_user()`**  
   ```python
   if not password:
       password = secrets.token_urlsafe(24)
       print("\nВАЖНО: создан временный пароль администратора:")
       print(password)
   ```
   - **Вход:** отсутствие `UYUT_BOOTSTRAP_ADMIN_PASSWORD`.  
   - **Выход:** пароль в stdout → в `docker logs`/CI.  
   - **Опасность:** высокая, если пароль изначальный и остался в логах.

**Что нельзя проверить чтением:** реальные значения `UYUT_SECRET_KEY`, `UYUT_BOOTSTRAP_ADMIN_PASSWORD`, `UYUT_DEMO_*`; наличие `.env` в репозитории; права на `hotel_management.db`.

## A05 — Injection (SQL, command, HTML)

**Нашел.**

1. **SQL — все запросы параметризованы.** Проверил `admin.py`, `auth.py`, `public.py`, `features.py`, `payments.py`, `utils.py`. `next_id` строит f-строку по белому списку таблиц/полей + regex на префикс — корректно.

2. **`routes/auth.py` — строки вида `flash(str(e) if isinstance(e, ValueError) else '...', 'danger')`**  
   `ValueError` от `datetime.strptime("abc", '%Y-%m-%d')` даёт `time data 'abc' does not match format '%Y-%m-%d'`.  
   - **Вход:** POST `/booking/BRxxx` с `check_in=abc`.  
   - **Выход:** гостю показывается Python-текст исключения.  
   - **Опасность:** низкая. Утечка деталей + удобно для fuzzing.

3. **`templates/booking.html`, `templates/rooms.html`, `templates/room_detail.html`**  
   Inline `onerror="this.src='...'"`, `onclick="this.previousElementSibling.value=..."`, `onsubmit="return confirm('Удалить гостя {{ c.Фамилия }} {{ c.Имя }}?...')"` —  
   **Последний случай:** в `templates/admin/clients.html` в `onsubmit` подставляется ФИО через Jinja. Jinja экранирует `'` в `&#39;`, поэтому **в HTML-атрибут подставить пробой нельзя**. Чисто.

4. **`templates/admin/bookings.html` — `status-{{ b.Статус|replace(' ','-') }}`**  
   Значение идёт в `class="..."` без проверки. Если кто-то когда-нибудь добавит статус с `"` или пробелами — превратится в инъекцию классов. Сейчас статусы фиксированы константой `STATUSES`. Чисто, но хрупко.

5. **Command injection** — `subprocess`, `os.system`, `eval`, `exec`, `pickle.loads` не используются. Чисто.

## A06 — Insecure Design

**Нашел.**

1. **`routes/payments.py` — гонка закрыта**: `BEGIN IMMEDIATE`, повторный `SELECT 1 FROM Платежи WHERE ... Статус='succeeded'`, `UPDATE ... WHERE Оплачено=0` (через проверку до). Хорошо.

2. **`routes/auth.py` — rate-limit больше не обходится форматами телефона** (identifier нормализуется). Хорошо.

3. **Жёсткая привязка админ-логина к строке `admin`** осталась:  
   ```python
   if login_value.lower() == 'admin':
       ... WHERE u.Роль = 'admin' LIMIT 1
   ```
   - **Вход:** второй админ с логином `admin2` в таблице `Пользователи`.  
   - **Выход:** войти он сможет только по телефону через fallback-запрос.  
   - **Опасность:** низкая (доступности), но плохо масштабируется.

4. **`routes/admin.py` — `admin_booking_add`** — все проверки дат корректны, но `admin_booking_update` не запрещает перевод `Завершено → Подтверждено`.  
   - **Вход:** POST `status=Подтверждено` на завершённую бронь.  
   - **Выход:** статус меняется без конфликт-чека.  
   - **Опасность:** низкая (админ сам).

## A07 — Authentication & Session

**Нашел.**

1. **`routes/auth.py` — Rate-limit теперь нормализует identifier**, но **остаётся привязка к IP**: `client_ip = request.remote_addr or 'unknown'`.  
   - **Вход:** атака через прокси/ботнет с 5 разных IP.  
   - **Выход:** обход блокировки.  
   - **Опасность:** средняя. По умолчанию Flask берёт `remote_addr`, за прокси это адрес прокси → все пользователи за одним прокси делят счётчик.

2. **`app.py` — нет ротации CSRF-токена между сессиями.**  
   Токен живёт в сессии, пересоздаётся только при `session.clear()` (login/logout).  
   - **Опасность:** низкая при HttpOnly+SameSite=Lax, но при XSS даёт полный контроль.

3. **`app.py` — `PERMANENT_SESSION_LIFETIME = 60 * 60 * 8`, нет idle-таймаута.** Сессия живёт 8 часов, даже если пользователь ушёл.

4. **`routes/auth.py` — все успешные и неуспешные входы не пишутся в `Журнал_действий`** (см. A09).

**Что нельзя проверить:** реальный HTTPS-контур, HSTS-предзагрузку, ротацию `UYUT_SECRET_KEY`.

## A10 — Mishandling of Exceptional Conditions

**Нашел.**

1. **`routes/auth.py` — `flash(str(e) if isinstance(e, ValueError) else '...')`.**  
   `ValueError` от `strptime` содержит текст исключения → утечка деталей в UI. Низкая.

2. **`routes/auth.py` — `create_booking`** — `except Exception as e: conn.rollback()` без проверки `conn.in_transaction`. В sqlite3 при уже закрытой транзакции падения нет, но лучше защищаться.

3. **`payments.py` — `except Exception: conn.rollback()`** — стиль сохранён, но не логирует `e` явно (только `logger.exception`).

4. **DoS-вектор:** `utils.next_id` линейно сканирует таблицу (`SELECT field FROM table WHERE field LIKE 'prefix%'`). При большом N и частых POST — деградация. Не security, но эксплуатационно.

**Что нельзя проверить:** поведение SQLite под нагрузкой, срабатывание watchdog, таймауты БД.

**Нашел.**

Нужно удалить лишний.

2. **`auth.py` (корневой) `password_matches`** — комментарий про миграцию legacy-паролей, но самой миграции нет. Мёртвый код, но безвредный.

3. **Два `auth.py`** — корневой (проверки доступа) и `routes/auth.py` (регистрация/вход). Имя вводит в заблуждение, лучше `routes/guest.py` или `routes/session.py`.

4. **`routes/public.py`** — заканчивается комментарием `# ============= АДМИН-ПАНЕЛЬ =============`, но админских роутов внутри нет. Устаревший комментарий.

5. **`hotel_logic.py`** совмещает миграции (`ensure_extra_rooms`, `ensure_extended_schema`), бизнес-логику услуг (`service_total`) и аудит (`log_action`). Лучше разделить: `migrations.py`, `services.py`, `audit.py`.

## Разбиение модулей на под-файлы

- **Python:** логика разнесена по `routes/*`. OK. Но `hotel_logic.py` перегружен (см. выше).
- **HTML:** шаблоны в `templates/` и `templates/admin/`. OK.
- **CSS:** `style.css` и `admin.css` — OK, но `style.css` ~950 строк, тянет на разделение.
- **JS:** `base.html` содержит авто-вставку CSRF-токена (inline). Против строгого CSP. Стоит вынести в `static/js/csrf.js`.
- **Inline CSS/JS в шаблонах:** `booking.html`, `contact.html`, `room_detail.html`, `profile.html` — большие `<style>` блоки. Мешает CSP.

## Что нельзя проверить чтением кода

- Реальные значения секретов (`UYUT_SECRET_KEY`, `UYUT_BOOTSTRAP_ADMIN_PASSWORD`, `UYUT_DEMO_*`) и наличие `.env` в репозитории.
- Права ФС на `hotel_management.db` и папку `static/images/rooms/`.
- Версии Flask/Pillow, реально установленные на боевом сервере.
- Настройки reverse-proxy (HTTPS, HSTS, WAF, размер запроса).
- Реальное поведение `\` в `next` в браузерах (проверено на уровне кода — фильтр `'\\' not in next_page` есть, но нужен живой тест).
- Куда пишутся `current_app.logger.*` — централизованно или в stderr.
- Наличие `.env` в `.gitignore`.
- Поведение SQLite под нагрузкой и наличие WAL.
