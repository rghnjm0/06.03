# АИС «Уют» — рабочая версия

Flask-приложение для управления небольшим отелем: сайт, единая авторизация, бронирования и админ-панель.

## Запуск

Для Windows можно использовать `START_UYUT.bat`. Вручную:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Откройте: `http://127.0.0.1:5000/`

Перед production-запуском задайте уникальный `UYUT_SECRET_KEY`, включите HTTPS и `UYUT_ENV=production`.

## Единая авторизация

Для всех пользователей используется единая страница `/login`. Данные учётных записей не выводятся в интерфейсе и документации.

## Логика бронирований

- Номер получает статус **«Занят»**, если на текущую дату есть активное проживание.
- **«Будет занят»** — если есть будущая активная бронь.
- **«Свободен»** — если пересечений с активными бронями нет.
- Прошедшие активные брони автоматически становятся **«Завершено»**.
- При создании брони проверяются даты, вместимость и пересечение с другими бронями.
- Даты заезда/выезда работают по стандартному правилу: выезд в день X освобождает номер для следующего заезда в день X.
- Отменённые брони не блокируют номер.
- Сумма считается по количеству ночей, предоплата — 30%.

## Админ-панель

- Дашборд с актуальным состоянием номерного фонда.
- Номера: добавление, редактирование, удаление без истории броней.
- Бронирования: поиск, фильтры, создание, смена статуса, проверка конфликтов.
- Оплата: отметка счёта как оплаченного и выбор способа оплаты.
- Гости: поиск, добавление, редактирование, карточка гостя и история бронирований.
- Отчёты: количество броней, стоимость проживания, оплаченная сумма, статистика по категориям и месяцам.

## Структура Python

- `app.py` — запуск приложения.
- `db.py` — SQLite и начальная база.
- `utils.py` — статусы номеров, доступность и расчёты.
- `routes/public.py` — публичная часть сайта.
- `routes/account.py` — HTTP-маршруты регистрации, входа, профиля и бронирований гостя.
- `security.py` — декораторы проверки доступа.
- `services/passwords.py` — хеширование, проверка и валидация паролей.
- `services/auth.py` — поиск учётной записи по логину/телефону; без Flask-маршрутов.
- `routes/admin.py` — вся логика админ-панели.

## Расширенная логика
Добавлены: проверка доступности по датам, двухшаговое бронирование, дополнительные услуги, календарь номерного фонда, заселение/выселение, финансовый раздел, отчёты, журнал действий, поиск гостей и защита входа с ограничением попыток.

## Оплата в демо-режиме

Внешние платёжные сервисы и SMS полностью отключены. Гость может нажать кнопку «Оплатить» после создания брони — система сразу отметит 30% предоплаты как полученную, но реальные деньги никуда не списываются. Платёж записывается в базе как «Онлайн (демо)», чтобы его было видно в личном кабинете и админ-панели.

Для запуска достаточно установить зависимости и запустить Flask: `pip install -r requirements.txt`, затем `python app.py`.

## Безопасность и обслуживание

- Реальная БД не должна коммититься в Git; для разработки используйте обезличенную БД.
- Перед миграциями делайте резервную копию.
- Для восстановления доступа: `python reset_access.py`.
- Пароли: минимум 12 и максимум 256 символов; в БД хранятся только хэши.
- Подтверждение бронирования повторно проверяет занятость номера внутри транзакции.
- Демо-оплата не списывает реальные деньги и не является платёжным шлюзом.
- `SECURITY_NOTES.md` — единственный актуальный документ по безопасности.

## Проверки качества и миграции

Установка инструментов разработчика: `python -m pip install -r requirements-dev.txt`.

Перед отправкой изменений запускайте:

- `python -m pytest -q` — тесты бизнес-правил;
- `python -m ruff check .` — проверка стиля и потенциальных ошибок;
- `python -m compileall -q .` — проверка синтаксиса.

Для существующей БД один раз зафиксируйте исходную схему: `alembic stamp 0001_baseline`.
Новые изменения схемы оформляйте ревизиями Alembic (`alembic revision -m "описание"`)
и применяйте командой `alembic upgrade head`. Для отдельной БД можно задать `UYUT_DB_PATH`.
Текущие `ensure_*_schema()` оставлены как совместимый механизм инициализации старых
установок; перевод всех исторических изменений на ревизии выполняется постепенно.

## Проверка качества и тесты

Установите зависимости для разработки и запустите проверки:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
python -m ruff check .
```

Тесты используют отдельные временные SQLite-базы и не должны изменять рабочую
`hotel_management.db`.
